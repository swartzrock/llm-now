Grounding Context

Codebase Context

The values are already defaults, not requirements. Today the native router embeds hey, minimum fuzzy phrase length 4, minimum similarity 65, and minimum margin 15. A missing TOML file is valid and read-only. The useful design question is therefore not whether compiled fallbacks continue to exist—they must—but how users discover, override, inspect, and deliberately pin them.

Two implementations

TypeScript runs natively; the retained Python example is an independent test oracle. Both currently duplicate the four defaults.

Closed TOML root

wake_words is special and every other root table is parsed as an alias profile. New global controls need a reserved home.

Read-only zero config

Missing config resolves to working defaults. Ordinary commands do not enter the voice path, and voice config has no writer today.

Fail-closed router

Fuzzy scores are only part of selection. Digit equality, span length, stage order, and ambiguity rejection provide separate guardrails.

Durable write precedent

The alias store already uses explicit user action, restrictive permissions, locking, a temporary file, and atomic rename.

Observable evidence exists

Rejected route results retain best and runner-up scores, but current diagnostics surface only the reason.

Topic Axes

1. Creation trigger and filesystem ownership

When is llm-now entitled to create durable user state, and how does the user inspect or opt into it?

2. Schema, precedence, and fallback semantics

Where do global controls live, and what precisely happens when the file or one field is absent?

3. Routing tunability and safety feedback

Which controls are safe to expose, and how can users tune them without guesswork or privacy leakage?

4. Compatibility, evolution, and parity

How do native behavior, the Python oracle, existing files, docs, and release boundaries remain aligned?

1

Explicit and Observable Voice Configuration

Confidence 93%Complexity Medium

Description: Make configuration a deliberate CLI lifecycle—conceptually voice config init, show, check, and path. Ordinary --voice routing remains side-effect-free. show works even with no file and labels each effective value as a compiled fallback or TOML override; init atomically writes a commented, owner-controlled snapshot after explicit user action.

Axis
Creation trigger and filesystem ownership
Rationale
Users gain discoverability and editability without a file appearing merely because they routed one prompt. The same surface becomes the support contract for path, parsing, and provenance.
Basis
direct: missing voice config is currently a valid read-only state, docs assign creation to the user, and the alias store already demonstrates explicit atomic persistence. external: Ansible and AWS separate configuration initialization and inspection from ordinary execution.
Downsides
Adds a small command surface and a writer. Command naming must fit llm-now's existing CLI grammar rather than forcing a nested shape that feels foreign.
Decision test
Can a user discover every effective value and deliberately create an editable file without normal routing mutating their config directory?
2

Safe Routing Policy Contract

Confidence 91%Complexity Medium

Description: Reserve a global [routing] table for min_fuzzy_phrase_length, min_similarity, and min_margin. Validate them as bounded soft controls. Keep digit equality, candidate-span compatibility, route-stage priority, and fail-closed ambiguity behavior as non-overridable invariants. Configuration then changes sensitivity, not the router's fundamental safety model.

Axis
Routing tunability and safety feedback
Rationale
The user can edit the values that actually govern fuzzy acceptance while the product stays honest about which protections are never disabled.
Basis
direct: the three values are already coherent fuzzy-policy constants, while digit equality, length compatibility, stage ordering, and ambiguity rejection are separate checks. The closed TOML root requires a reserved namespace to avoid treating a global table as an alias profile.
Downsides
The name routing becomes reserved and may collide with a user's alias of the same name. Bounds need justification and clear validation messages.
Decision test
Can users tune false rejects without gaining a way to bypass guards that prevent costly or wrong-destination requests?
3

Rolling Defaults, Optional Pinning

Confidence 90%Complexity Low

Description: Define absence as inheritance. With no file—or with one field removed—llm-now uses the current compiled fallback. An explicitly initialized file is a user-owned snapshot of the values written and is never silently refreshed. The template explains “delete this line to inherit the application default”; wake_words = [] remains the explicit way to disable stripping.

Axis
Schema, precedence, and removed-field fallback semantics
Rationale
This resolves the tension between safe evolution and reproducibility. Users can follow future defaults, pin today's behavior, or restore one value to inheritance without deleting the rest of their profiles.
Basis
direct: missing TOML, omitted wake_words, and omitted speech-profile values already inherit independently. reasoned: auto-created complete files would otherwise ossify every current default even for users who never intended to customize them.
Downsides
A generated complete snapshot opts users out of future default improvements until they delete fields. Comments and effective-value provenance must make that consequence clear.
Decision test
Is the result deterministic for no file, a complete initialized file, and that same file with any one key removed?
4

Explain and Replay Before Tuning

Confidence 84%Complexity Medium

Description: Add a local, no-LLM way to evaluate an utterance against the effective configuration. It reports the deciding stage, best and runner-up scores, configured boundaries, and the exact failed gate. Default diagnostics remain privacy-preserving by omitting transcript and question content; an explicit replay input can provide richer local analysis.

Axis
Routing tunability and safety feedback
Rationale
Three editable numbers are otherwise opaque. Explain/replay lets users determine whether length, similarity, margin, digits, or ambiguity rejected a route before they weaken a threshold by guesswork.
Basis
direct: route results already retain best and runner-up scores; rejection happens before any LLM request, and current diagnostics discard those score details. external: sensitivity controls are meaningful only when users can observe their false-positive/false-negative tradeoff.
Downsides
Adds a diagnostic surface and requires careful redaction. It should remain a focused evaluator, not grow into recording, calibration, or telemetry machinery.
Decision test
Can a user explain “why did this almost match?” without submitting a prompt, collecting audio, or exposing the question text in routine diagnostics?
5

Configuration Parity as an Executable Contract

Confidence 92%Complexity Medium

Description: Expand the shared parity corpus to include configuration state and expected behavior: absent file, each omitted field, explicit thresholds at important boundaries, effective values, route outcomes, scores, and diagnostic categories. Native TypeScript and the retained Python example remain independent consumers of the same behavioral cases; packaged execution stays Python-free.

Axis
Compatibility, evolution, and native/Python parity
Rationale
Every newly editable value creates another drift opportunity. Shared cases protect semantics without making the Python example a runtime dependency or forcing both implementations to import one generated defaults module.
Basis
direct: both suites already consume one language-neutral routing corpus, including scores and offsets, while release-policy tests explicitly keep Python out of native jobs. Configuration cases extend an established contract rather than introducing a new dependency.
Downsides
The corpus grows and must distinguish parser-specific validation from cross-language behavior. Over-sharing implementation data would weaken the oracle's independence.
Decision test
Could a default, omission rule, or threshold boundary change in TypeScript while the Python oracle still passes? If so, the contract is incomplete.

Rejection Summary

The cut is intentionally skeptical. Useful implementation details were folded into stronger directions; larger workflows were rejected when the codebase did not demonstrate enough need.
