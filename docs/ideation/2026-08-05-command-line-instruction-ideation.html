Command-line instructions for LLM-Now

Yes: a request-scoped --instruction is a strong fit. The best version is universal across selectors, remains separate from the user prompt, and replaces—rather than silently appends to—an alias’s saved instructions for that run.

Grounding Context

The transport seam already exists

Alias selection already carries one optional instructions string into a shared generation tail. BYOK Runtime 2.2 maps it to each provider’s native behavioral channel without joining it to the user prompt.

The missing capability is request resolution

Strict argument parsing rejects --instruction today. Explicit provider/model calls deliberately construct instruction-free selections, even though the runtime can already accept the value.

Existing contracts constrain the design

Prompt text has exactly one input source; successful stdout is byte-exact model output; runtime failures redact active instructions; saved instructions are nonblank and reject unsafe control characters.

External precedent separates replacement from append

Claude Code gives replacement and append different flags. Other LLM CLIs support request-scoped behavioral text, but their varied names reinforce the need for an explicit llm-now contract.

The key uncertainty is not feasibility. It is precedence: when an alias has saved instructions and the command supplies another value, the tool must choose replacement, composition, or conflict. One runtime value and the strongest external precedent favor replacement.

1

Invocation syntax and input-source ergonomics

1. Universal request-scoped --instruction

Description: Accept one exact --instruction <text> value with positional aliases, --alias, and explicit --provider/--model selection. It modifies only the behavioral channel; the user prompt continues to come from the existing --input, stdin, or alias-only interactive path.

Rationale
It exposes an existing runtime capability without forcing temporary alias creation and preserves every established prompt-input contract.
Confidence
96%
Complexity
Medium

Basis — direct: src/args.ts already normalizes multiple selector forms; src/app.ts routes them into a shared generation tail that accepts prompt and instructions separately.

Downsides: The flag expands the tested invocation matrix and makes long or multiline values awkward in ordinary shell syntax.

2

Alias-versus-command-line instruction precedence

2. Command-line instruction replaces the alias default

Description: Treat the saved alias instruction as a default. With no new flag, the alias behaves exactly as it does today; with --instruction, the command-line value is the complete effective instruction for that invocation and the saved alias remains unchanged. Never concatenate the two under this flag.

Rationale
Users can answer “what instruction did this request use?” with one value and one precedence rule, independent of provider.
Confidence
95%
Complexity
Low

Basis — direct + external: Alias records and runtime requests each carry one optional instruction string. Claude Code independently separates replacement from append, showing that composition should not hide behind the same option.

Downsides: Users who intuitively expect additive behavior may be surprised unless help text states the override rule plainly.

3

Provider-runtime fidelity and observability

3. Provider-native instruction delivery

Description: Resolve the effective instruction once, pass it unchanged through the existing RuntimeGateway field, and let BYOK Runtime remain the sole owner of provider-native translation. Prompt concatenation is never a fallback; an incapable future adapter should fail rather than silently omit or role-change an explicit instruction.

Rationale
One neutral contract supports every current and future provider without provider-specific branching in llm-now.
Confidence
95%
Complexity
Low

Basis — direct: src/runtime.ts already constructs separate prompt and instructions fields, and BYOK Runtime 2.2 documents exact provider-native mapping and omission semantics.

Downsides: Native channels do not guarantee identical role priority across providers; the product can promise faithful transport, not identical model behavior.

4

Validation, privacy, and failure behavior

4. Shared structural validation with exact preservation

Description: Give ephemeral and saved instructions the same textual contract: reject blank values and prohibited control characters, but preserve every accepted byte, including leading/trailing whitespace and line breaks. Keep persistence-only credential and vault work out of the request path while reusing existing runtime failure redaction.

Rationale
One definition of valid instruction text prevents alias and command-line behavior from drifting while keeping one-shot calls stateless.
Confidence
93%
Complexity
Low

Basis — direct: src/aliases.ts defines the nonblank/control invariant; alias and runtime tests already prove exact preservation; credential screening is tied to saving persistent state.

Downsides: The validation rule becomes a cross-surface contract and must stay consistent if either the alias schema or CLI later evolves.

5

Validation, privacy, and failure behavior

5. Ephemeral, not confidential

Description: Describe --instruction as “not persisted by llm-now,” not as a secret-input mechanism. Continue redacting the active value from runtime failures and never echo it in routine diagnostics, while documenting that shell history, process inspection, CLI-provider child arguments, provider retention, and successful model output can still reveal it.

Rationale
The feature’s privacy boundary remains accurate, useful, and testable instead of turning convenience into secret theater.
Confidence
92%
Complexity
Low

Basis — direct: Runtime tests already redact raw and escaped instruction values from failures, preserve successful output, and use fixed presence-only markers for CLI fixtures. The README already documents provider and child-argument exposure.

Downsides: A clear warning adds documentation weight to a small flag, and llm-now cannot redact content deliberately echoed by the model without breaking stdout fidelity.

6

Provider-runtime fidelity and observability

6. Provider-neutral “instruction” terminology

Description: Keep the public option singular and provider-neutral: --instruction supplies one request-scoped behavioral instruction. Avoid promising a universal “system prompt,” because the runtime maps the same logical value to system messages, Ollama’s system field, Claude’s append-system option, and Codex developer instructions.

Rationale
The name matches the runtime abstraction and OpenAI’s request vocabulary without overstating cross-provider equivalence.
Confidence
91%
Complexity
Low

Basis — direct + external: BYOK Runtime exposes instructions?: string, the alias schema already calls the field instructions, and OpenAI’s Responses API uses instructions for request-scoped behavior.

Downsides: Users familiar with --system may search for that term, and the singular CLI name differs slightly from the internal plural field.

7

Alias-versus-command-line instruction precedence

7. Minimal core with explicitly deferred companions

Description: Keep the first product contract to one universal replacement flag. Evaluate suppression, file input, and composition as separate future questions instead of letting them quietly complicate this feature.

Core now

--instruction <text> works across selectors, replaces any alias default for one run, preserves bytes, and uses the existing provider-native lane.

Evaluate separately

--no-instruction, --instruction-file, and --append-instruction each introduce a distinct user need and contract.

Rationale
The smallest evidenced contract solves the motivating problem and leaves later additions compatible rather than speculative.
Confidence
90%
Complexity
Low

Basis — direct + external: The current runtime needs only one optional value, while the rejected companions require new states, file semantics, or composition rules with no demonstrated demand in this request.

Downsides: Users cannot temporarily suppress an alias instruction, avoid inline shell quoting through a file option, or append to a saved instruction in the first version.
