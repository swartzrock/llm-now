Direction at a glance

Goal Capsule

Objective

Create 20 campaign-ready recipe candidates that make readers want to copy a command, install llm-now, or click through to see what else it can do.

Product authority

This plan owns the candidate slate and its slideshow presentation. Final social posts, winner selection, and the permanent cookbook remain separate work.

Open blockers

None before planning. The eventual shortlist is a downstream editorial choice, not a blocker for producing the candidate deck.

The thing to preserve

Product Contract

Summary

Produce a self-contained HTML slideshow of 20 audience-labeled llm-now recipe concepts, sequenced as a campaign arc and detailed enough to choose which recipes deserve full production.

Problem Frame

The README teaches installation, input modes, aliases, and provider selection, but its intentionally compact examples cannot demonstrate the range of situations where a one-shot text model becomes useful. A publicity campaign needs moments with stronger curiosity gaps than “summarize this text.”

The opportunity is not to pretend the CLI has tools, memory, or repository awareness. It is to show that familiar shell producers and consumers supply the missing context and destination, making a narrow text primitive unexpectedly versatile.

Key Decisions

Campaign arc with audience lanes

Alternate serious, useful, playful, and surprising concepts while retaining audience tags. Governs R1, R2, R3.

Mixed-audience showcase

Reach beyond a developer-only cookbook so the breadth itself demonstrates the product.

(session-settled: user-directed — chosen over a terminal-developer-only collection: variety is part of the desired product demonstration)

Human review before mutation

Recipes may generate text for consequential actions, but they never pipe model output directly into an executor. Governs R6.

Candidate depth, not finished tutorials

Show enough command detail to judge the idea while reserving production polish for shortlisted recipes. Governs R5.

Recipe 01 · DeveloperHuman-reviewed

Let the staged diff write its own commit message.

Social hook: “I stopped describing my diff to an AI. The diff is already text.”

Audience
Developers using Git
Outcome
A reviewable Conventional Commit message
Platform
macOS, Linux, Windows shell equivalents
{ printf '%s\n\n' 'Write a Conventional Commit message for this staged diff. Return only the message.'; git diff --cached; } | llm-now haiku
Why it earns the click + production note

Why: The command makes the Unix-composition story visible in one line and improves on “ask chat to write a commit message” by supplying the exact staged context.

Production note: Generate message text only. The finished recipe must tell the reader to review it before running git commit; never pipe model output into a shell or Git command.

Recipe 10 · Power usermacOS · Stickies

Leave future-you a pep talk in Stickies.

Social hook: “My terminal asked a model for two encouraging sentences, then left them on my desktop for tomorrow.”

Audience
Mac automation fans and productivity tinkerers
Outcome
A generated note stored in Stickies
Platform
macOS only
note=$(llm-now haiku --input "Write a specific two-sentence pep talk for someone finishing a difficult project.")
osascript - "$note" <<'APPLESCRIPT'
on run argv
  tell application "Stickies" to make new note with properties {body:item 1 of argv}
end run
APPLESCRIPT
Why it earns the click + production note

Why: This is whimsical, visible, and unmistakably not a developer-only use case. It develops the user’s original Stickies idea into a safe argument-passing shape.

Production note: Validate the AppleScript against supported macOS versions before publishing and explain that the script creates a note but does not grant llm-now app-control capabilities.

How the slate earns its keep

Success Criteria

  • Selection quality: A reviewer can shortlist candidates from the overview, then judge any finalist from one slide without needing the README open beside it.
  • Audience range: The deck’s campaign order visibly satisfies R2.
  • Product truth: Every candidate satisfies R9, R10, and R11.
  • Campaign fit: Every candidate can become one daily post per R1; the twenty-first day remains available for launch, recap, or the winning full cookbook.
  • Safety: Every candidate satisfies R6.

Acceptance Examples

  • AE1. Covers R1, R2, R7. A reviewer opens the file, sees all 20 candidates in campaign order, and jumps directly to any full slide.
  • AE2. Covers R5, R6. The commit-message candidate generates reviewable prose but never invokes git commit or a shell with model output.
  • AE3. Covers R4. The Stickies candidate is visibly labeled macOS-only before the reader reaches its command sketch.
  • AE4. Covers R9, R10. Every non-interactive command supplies one input source and names either an alias or an explicit provider/model pair.

Keep the slate selectable

Scope Boundaries

In this plan

Twenty recipe concepts, audience and platform labels, campaign hooks, truthful command sketches, selection rationale, and production caveats.

Deferred for later

Winner selection, full tutorials, exact lazygit configuration, platform variants, screenshots, terminal recordings, and the permanent cookbook location.

Outside this work

Final Twitter/X or LinkedIn copy, publishing automation, engagement analytics, and recipes that execute generated commands without review.

Dependencies / Assumptions

  • The examples assume the reader has configured aliases such as local or haiku; full recipes must teach readers to substitute their own alias.
  • Platform-specific app and shell integrations require validation on their target operating system before publication.
  • Commands that include private text, filenames, code, or logs require provider-appropriate data handling and redaction guidance.
